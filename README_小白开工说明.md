# 小白开工说明｜先看这里

你现在不用自己设计目录，也不用把 7 份长提示词每次复制一遍。

## 一、你手里的这个文件夹是什么

这是“正式开发项目根目录”。

最重要的 3 个位置：

```text
AGENTS.md
docs/codex/
prototype/
```

### AGENTS.md
这是 Codex 每次进入项目都应该遵守的“长期总规矩”。

### docs/codex/
这里放 7 份施工任务书：

```text
00 总控
A 教学核心
B 课程资源
C 实验定义
D 实验运行底座
E 实验课堂
F 成绩学情审计
```

### prototype/
这里放最终 HTML。
Codex 做前端时必须对着它实现，不要重新设计一套。

# 二、第一次只做 4 步

## 第 1 步：把整个文件夹解压到一个固定位置

建议：

```text
D:\Yueke\CyberRange\
```

不要放桌面临时目录，也不要今天一个目录、明天换一个目录。

---

## 第 2 步：初始化本地 Git

你不需要 GitHub。

双击根目录：

```text
01_初始化本地Git.cmd
```

它只会把当前文件夹变成本地 Git 仓库，不会上传互联网。

如果提示电脑没有 Git，让 Codex/你先安装 Git for Windows 后再运行。

---

## 第 3 步：打开 Codex，选择这个“项目根目录”

不要一开始就开 7 个窗口。

先开窗口 0。

把下面一句发给 Codex：

```text
先读取根目录 AGENTS.md，再读取 docs/codex/00_总控集成_P0-CONTRACT-FREEZE.md。
把后者作为本窗口唯一施工任务书。
先扫描当前仓库并复用现有代码，然后直接执行 P0-CONTRACT-FREEZE。
不要只给方案，要实际修改代码、migration、contract、公共组件和测试。
完成后提交本地 Git，并按 AGENTS.md 的最终回复格式给我结果。
```

---

# 三、窗口 0 通过以后再开 A～F

等窗口 0 明确告诉你：

```text
P0 PASS
A～F 可以并行启动
```

再开 6 个 Codex 聊天。

**每一个都选择“工作树 / Worktree”，起点选择 integration。**

不要让 6 个窗口都选“本地”，否则可能互相覆盖代码。

---

# 四、A～F 你不需要粘贴长任务书

只发一句启动语。

具体启动语已经放在：

```text
Codex_7窗口启动话术.md
```

Codex 会自己读取本地任务书。

# 五、最简单的并行顺序

```text
窗口 0：先做 P0 Contract Freeze

P0 PASS 后：

窗口 A：教学核心
窗口 B：课程资源
窗口 C：实验定义
窗口 D：真实 Docker 运行底座
窗口 E：实验课堂
窗口 F：成绩学情审计
```

其中最难、最关键的是 D。

D 必须做真的：

```text
Docker
隔离网络
Web Terminal
RSA 命令
真实自动判分
销毁/恢复
```

不能只是页面模拟。

# 七、非常重要

如果你已经有正式源码：

**不要把这个空骨架覆盖你的源码。**

正确做法：

1. 把 `AGENTS.md`
2. `docs/codex/`
3. `prototype/`
4. `docs/procurement/`

复制进你现有源码的根目录。

然后让窗口 0 先扫描现有代码，复用现有工程。

空的 frontend/backend 目录只是给“从零新建工程”使用。
