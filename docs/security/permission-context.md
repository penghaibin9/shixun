# 权限上下文冻结（v1）

每个已认证请求解析为：`user_id`、`role`、可选 `teacher_id`、可选 `student_id`、`permissions`、`course_ids`、`class_ids`。课程和班级范围在服务端每次请求解析，不能只依赖前端或把全量范围永久塞入令牌。

教师只能访问本人课程、班级和班内学生；学生只能访问自己的课程、签到、作业、实验、日志和成绩；管理员的基础设施高风险操作必须写入审计。前端角色切换仅为验收展示，生产环境不得允许普通用户切换身份。

身份提供方式按环境强制隔离：`development`（开发）和 `test`（测试）环境可显式使用 `X-User-Id` 等请求头完成本地契约验收；`production`（生产）环境无条件拒绝这些开发请求头，只接受认证中间件预先写入 `request.state.user_context` 的可信 `UserContext`（用户上下文）。生产环境尚未接入认证中间件时应返回 `AUTH.TRUSTED_IDENTITY_REQUIRED`，不得降级为可伪造请求头。

教师学生管理接口必须同时校验教师身份、任课关系与 `class_ids` 数据范围。教师可以加入已有学生账号或解除本人班级的 `class_membership`，但不能查看全校学生、删除全局账号、修改角色或操作其他教师的班级。学生角色不得访问任何教师学生管理接口。

服务层使用 `UserContext` 进行权限和数据范围判断，禁止分散的角色字符串判断。所有拒绝均返回标准错误信封，且不泄露其他用户或资源是否存在。

E 向学生分发 D 所属日志制品时不得放宽 D 的普通实例所有权规则。E 只有在确认 `student_log_assignment`、课程、班级、实验发布和精确引用集合后，才能使用 `YUEKE_LOG_DISTRIBUTION_SIGNING_KEY` 签发最长 60 秒的分发授权；D 必须重新验证签名、有效期、学生身份、课程/班级范围以及每个 D 源事实。D 再使用独立的 `YUEKE_ARTIFACT_STORAGE_SIGNING_KEY` 签发存储能力，E 不得持有该密钥。两把密钥均至少 32 字节，只能由环境密钥注入；缺失或过短时必须安全失败，禁止写入源码、日志或下载地址。
